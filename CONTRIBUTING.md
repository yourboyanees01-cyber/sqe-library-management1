\# Contributing to SQE Library Management System



This project follows a simple branching strategy. All new work should be 

done on a feature branch created from `main`, using the naming convention 

`feature/<short-description>` (e.g. `feature/add-book-search`) for new 

features, or `fix/<short-description>` for bug fixes.



Once a feature or fix is complete, changes should be pushed to the branch 

and a Pull Request opened against `main`. Commit messages should follow 

the Conventional Commits format (e.g. `feat: add book search`, 

`fix: correct overdue calculation`).



Pull Requests require at least one review approval before merging, and 

should be merged using "Squash and merge" to keep the commit history 

clean and linear.
